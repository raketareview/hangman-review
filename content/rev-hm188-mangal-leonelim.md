**2. Exceptions**

- Проброс исключений в сигнатурах методов- мусор
```java
public char getLetter(String prompt) throws BadInputException
```
Непроверяемые исключения, а исключение `BadInputException` непроверяемое, не нужно писать в сигнатурах.  

Проверяемые исключения, в отличие от непроверяемых, приходится писать в сигнатурах, поэтому их нужно перехватывать и вместо них кидать непроверяемые.  
*"ЧК", гл.7, "...проверяемые исключения"*

**4. class FileReader**

- Путь к файлу класс должен получать в конструктор. 

Иначе класс становится не универсальным.  
Допустим, в программе будет несколько разных текстовых файлов- на разных языках или по разным темам.  
Тогда вместо нескольких специализированных классов Словаря, где имя файла словаря будет жестко прописано в каждом из классов, 
можно будет использовать один универсальный класс Словарь.

**5. class HangmanArt**

Константный класс, в котором хранятся картинки виселицы
```java
public class HangmanArt {
  public static final String[] HANGMAN_STATES = {...}
}
```

- Соблюдай требования константных классов. 

Константные классы должны быть `final` и иметь приватный конструктор.  
Не должно быть возможности унаследоваться от константного класса или сделать его экземпляр.  
*Блох, "Java. Эффективное программирование", изд.3, гл.2.4*

- Функционал.

Хранить картинки отдельно от логики это хорошо.

Но если в той программе имеется ввиду объектно-ориентированное программирование, то в отдельном классе стоит не просто хранить картинки-константы, а сделать более сложную сущность- рендерер.  
Типа такого:
```java
public class HangmanRenderer {
  private static final String[] HANGMAN_STATES = {...}
  
  public void render(int stateNumber) {...} //Печатает картинку по её номеру
}
```

**6. class HangmanSession**

- Дублирование логики
```java
private boolean isGameOver() {
  return hint.indexOf(String.valueOf(BLANK)) == -1 || mistakeCount == GAME_OVER_MISTAKES;
}

private boolean isGameLost() {
  return mistakeCount == GAME_OVER_MISTAKES;
}

private boolean isGameWon() {
  return hint.indexOf(String.valueOf(BLANK)) == -1;
}

//ПРАВИЛЬНО:
private boolean isGameOver() {
  return isGameLost() || isGameWon();
}
```

- Не используй префиксную(++i) форму инкремента, используй только постфиксную форму инкремента(i++).

Эти инструкции имеют серьезное отличие.  
Чтобы не ввести в заблуждение ни себя, ни своих коллег, на уровне привычки используй только постфиксную форму инкремента
```java
++mistakeCount;

//ПРАВИЛЬНО:
mistakeCount++;
```
Если алгоритм построен так, что для него подходит только префиксная(++i) форма инкремента, то переделывай алгоритм под постфиксную форму(i++).
