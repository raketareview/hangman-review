**1. Нейминг**

- Не называй кастомный класс словом "List", если он не реализует стандартный интерфейс List
```java
public class RandomList {
  public static String getRandom(List<String> wordList) {
    //Возвращает случайное слово из списка wordList
  }
}        

//ПРАВИЛЬНО:
public class WordPicker {
  public static String getRandom(List<String> wordList) {...}
}    
```

- Венгерская нотация.

В названии переменных не пиши тип данных, к которым они относятся.  
И вообще не употребляй венгерскую нотацию.  
Название переменной должно отвечать на вопрос что хранит переменная, а не как хранит
```java
List<String> wordList
Set<String> setLetter
List<Integer> indexList 

//ПРАВИЛЬНО:
List<String> words
Set<String> letters
List<Integer> indexes 
```

- Методы должны называться стилем camelCase
```java
public String StorageLetter(String letter) 

//ПРАВИЛЬНО:
public String storageLetter(String letter) 

//БОЛЕЕ ЕСТЕСТВЕННО ЗВУЧИТ ТАК:
public String letterStorage(String letter) 
```

- Поля тоже camelCase
```java
String WordStartOfGame

//ПРАВИЛЬНО:
String wordStartOfGame
```

- Буквы это НЕ СТРОКИ. 

Потому что строка может состоять из любого количества символов, от нуля включительно.  
А буква это всегда только один символ.  
Поэтому не используй для них тип `String`, они должны быть `char`
```java
Set<String> setLetter

//ПРАВИЛЬНО:
Set<Character> letters
```

- Название должно объяснять, что делает метод. 

Этот метод берет слово и возвращает его маску
```java
String getStarsWord(String word) {
  //"привет" -> "******"    
}

//ПРАВИЛЬНО:
String toMask(String word) {...}
```

- Аббревиатуры в названиях лучше писать так же, как и другие слова
```java
public static String[] getASCII(...)

//ЛУЧШЕ:
public static String[] getAscii(...)
```
Например, какое название понятнее: `HTTPURL` или `HttpUrl`?

**3. Форматирование**

- Форматирование строк.

Если нужно печатать или создавать строку с более, чем одним подстановочным значением или значение вставляется внутрь сообщения, 
используй форматирование- тогда сразу будет виден весь шаблон
```java
System.out.println("У вас осталось " + (attempt - count) + " попыток");

//ПРАВИЛЬНО:
System.out.printf("У вас осталось %d попыток \n", attempt - count);
```

- Мысленные преобразования.

Не вставляй перевод строки в середину строк при распечатке.  
Иначе при чтении кода приходится мысленно "разворачивать" одну строку в несколько.  
Если нужно распечатать несколько строк, то печатай их или многострочными строками(""") или отдельными инструкциями печати.  
Тогда сразу будет видно, как текст будет выглядеть на печати:
```java
System.out.println(System.out.println("ВЫ ПРОИГРАЛИ...\n" + "Загаданное слово было: " + randomWord););

//ПРАВИЛЬНО:
System.out.println("ВЫ ПРОИГРАЛИ...");
System.out.println("Загаданное слово было: " + randomWord);
```

**4. class Wordbook**

+ 👍 По сути, это хранилище букв. 

Хранить введенные буквы в отдельном классе это хорошо.

- Нейминг.

Мне непонятно, почему этот класс называется "Книга слов", если он служит хранилищем не слов, а букв
```java
public class Wordbook {
  private final Set<String> setLetter = new HashSet<>();  

  public String StorageLetter(String letter) {
    //если letter состоит из одной буквы,
    //то записывает эту букву в setLetter
  }

```

- Нарушение принципа разделения команд и запросов. 

Этот метод совмещает команду и запрос.  
Команда: добавить букву в хранилище.  
Запрос: вернуть все хранимые буквы в виде строки
```java
public class LetterStorage {
  private final List<String> setLetter = new HashSet<>();  

  public String StorageLetter(String letter) {
    //если letter состоит из одной буквы,
    //то записывает эту букву в setLetter
  }
}
```
Метод должен или выполнять команду, или отвечать на запрос.  
Этот метод нужно разделить на несколько, каждый из которых будет делать что-то своё.
 
*Мартин, "Чистый код", гл.3, "Разделение команд и запросов"* 
```java
"Либо функция изменяет состояние объекта, либо возвращает информацию об этом объекте. 
Совмещение двух операций часто создает путаницу." - Мартин.
```

- Рефакторинг этого класса.

В текущем виде класс выглядит невнятным.

Для начала давай определимся, зачем вообще нужен этот класс.  
А после этого станет понятно, что он должен будет делать.  
То есть, станет понятен его SRP.

Итак, это хранилище букв, которые будет вводить юзер.  
Класс должен хранить эти буквы и обеспечивать базовый доступ к ним:
Добавить букву, прочитать все буквы, проверить наличие буквы в хранилище.  
Удалять букву из хранилища не надо- такой функционал не требуется этой игре от хранилища букв.  

Тогда хранилище должно выглядеть примерно так:
```java
public class LetterStorage {
  private final List<Character> letters = new ArrayList<>();  

  public void add(char letter) {
    //добавляет letter в letters
    //при попытке два раза добавить одну и ту же букву в хранилище- бросает исключение
  }

  public List<Character> getAll() {
    return List.of(letters);  //возвращаем не оригинал коллекции, а ее копию
  }

  public boolean contains(char letter) {
    //true если letter содержится в letters
  }
}
```

Фактически, получился класс с функционалом базового `List`, не правда ли?

Да, но есть важные нюансы:

🔹В `LetterStorage` есть только то поведение, которое необходимо сущности "Хранилище букв"- принцип минимального открытого интерфейса.    
В базовом List'e есть стопитсот другого поведения, которое не нужно сущности хранилища.  

🔹При попытке повторного ввода буквы в хранилище, бросается исключение.  
Такого поведения нет в базовом List'e.

Стоит ли ради таких небольших отличий от простого `List<Character>` делать специальный класс `LetterStorage`?  

Да, стоит- новые классы в ООП программе нужно делать тогда, когда мы выделили в программе новую сущность.  
Эту сущность и нужно сделать классом.  
В данном случае, это сущность "Хранилище букв".

**8. class Main**, содержит точку входа main

- Нарушение SRP.

Main должен только сконфигурировать зависимости и запустить программу.  
Управлять работой программы этот класс не должен.  
В Main'e возможен только диалог "Играть или выйти"- это все еще относится к ответственности конструирования и запуска системы.

Main ООП-шной виселицы должен выглядеть примерно так:
```java
public class Main {
  private final static String PATH = "words.txt";
  private final static String START = "Н";
  private final static String QUIT = "В";

  public static void main(String[] args) {
    Dictionary dictionary = new Dictionary(PATH);
    
    while(true) {
       String command = inputCommand();

       if(isStart(command)) {
          
          String word = dictionary.getRandomWord(); 
          Game game = new Game(word);
          game.start();

       } else if(isQuit(command)) {
         return;
       } else {
          //ввели неверную команду
       }
    }
  }

  private static String inputCommand() {
    //диалог с юзером: "[Н]овая игра или [В]ыход" 
    //возвращает только команду START или QUIT
  }

  private static boolean isStart(String command) {
    return command.equalsIgnoreCase(START);
  }

  //...
}
```
*Мартин, "ЧК", гл.11, "Отделение конструирования системы от ее использования"*

- Большой божественный метод.

Ацкий ад- метод `main()` размером 60 строк.  
Этот метод вообще нечитаем.  
Божественные методы разделяй на маленькие методы, каждый из которых должен делать одно дело на одном уровне абстракции.  

Например, смотрим на божественный метод и находим в нем отдельные смысловые блоки
```java
public static void main(String[] args) {
  //куча кода

  System.out.println("Введите букву:");
  String inputLetter = scanner.nextLine().toUpperCase();
  if (inputLetter.length() != 1) {
    System.out.println("Надо ввести только одну букву");
    continue;
  }

  //ещё куча кода
}
```

Что делает этот кусок кода? Он принимает от юзера буквы.  
Выносим этот код во вспомогательный метод:
```java
public static void main(String[] args) {
  //куча кода

  char letter = inputLetter();

  //ещё куча кода
}

private static char inputLetter() {
  Scanner scanner = new Scanner(System.in);
  System.out.println("Введите букву:");

  while(true) {
    String s = scanner.nextLine();
    if (s.length() == 1) {
      return s.charAt(0);
    }
    System.out.println("Надо ввести только одну букву");
  }    
}
```
