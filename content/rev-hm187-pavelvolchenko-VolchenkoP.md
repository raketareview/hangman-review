## ЗАМЕЧАНИЯ

**1. Нейминг**

- Старайся использовать стандартные общепринятые названия
```java
WordProvider(String resourceName)

//ЛУЧШЕ:
WordProvider(String filepath)
```

- Название обманывает.

Класс не рисует (draw) картинки, он хранит картинки
```java
public class HangmanDrawer {
  public String getHangmanArt(int mistakeCount)
}

//ПРАВИЛЬНО:
public class HangmanPicture {
  public String get(int mistakeCount)
}
```

- Если метод называется "проверить" (check), то результат этой проверки должен быть boolean.  
Если метод не возвращает boolean, значит он не выполняет проверку и не должен так называться
```java
void checkGameStatus()
```

**2. Форматирование**

- В строках не используй символы двойных кавычек.

Обрати внимание, что в текстах консольных программ никто никогда не использует символы двойных кавычек ("Double quotes").  
Вместо них используют одинарные ('Single quotes').
```java
System.out.println("Хотите сыграть еще раз? Введите 1 если \"да\" и любой другой символ если \"нет\".");

//ПРАВИЛЬНО:
System.out.println("Хотите сыграть еще раз? Введите 1 если 'да' и любой другой символ если 'нет'.");
```
Делают так специально, чтобы при форматировании не заморачиваться с экранированием.

**2. Нарушение DRY**

Магические буквы, числа, слова. Вводи константы 
```java
System.out.println("Хотите сыграть еще раз? Введите 1 если \"да\" и любой другой символ если \"нет\".");
return scanner.nextLine().trim().equalsIgnoreCase("1");

//ПРАВИЛЬНО:
private static final String START = "1"; 

System.out.printf("Хотите сыграть еще раз? Введите '%s' если 'да' и любой другой символ если 'нет'.", START);
return scanner.nextLine().trim().equalsIgnoreCase(START);
```

**3. Если в блоке if есть return(break, continue, throw, exit и т.д.), то else не пишется**

В этом случае неважно, будет else или нет, так как программа будет работать одинаково, а код без else будет выглядеть читабельней
```java
if (chosenWord.indexOf(normalized) != -1) {
  //...
  return AttemptResult.HIT;
} else {
  //...
  return AttemptResult.MISS;
}

//ПРАВИЛЬНО:
if (chosenWord.indexOf(normalized) != -1) {
  //...
  return AttemptResult.HIT;
} 
  
//...
return AttemptResult.MISS;
```

**4. Exceptions**

- Текст в Exception всегда должен быть на английском языке.
```java
throw new RuntimeException("Не удалось загрузить перечень слов", e); <-- Неправильно: сообщение в исключении не на английском языке
```
Исключение это не просто телеграмма, которая летит сквозь слои.

У exception особое назначение- если исключение вылетит и не будет перехвачено внутри программы, то аварийно прекратит выполнение программы.  
Тогда на экране будет распечатано сообщение эксепшена, и это сообщение должно быть понятно сисадмину в любой точке планеты.  
А значит, сообщение должно быть на английском.

Интерпретация исключения и перевод его на локальный язык должны происходить там, где это соответствует архитектуре программы.  
Или не происходить вовсе, если исключение не планируется перехватывать.

- Не бросай базовый exception. Конкретизируй ситуацию- бросай то исключение, которое подходит под этот конкретный случай
```java
throw new RuntimeException(String.format("Файл '%s' не найден в classpath.", resourceName));
```

**5. class WordProvider**

+ 👍Название класса и метода- норм.

+ 👍Класс соответствует SRP- он только загружает слова из файла и выдает случайное слово.

- Минимальный размер слов для загрузки в словарь.

Из файла читаются только те слова, которые содержат больше определенного количества букв
```java
List<String> filtered = strings.stream()
    .filter(word -> word.length() >= 4) 
```
Словарь не должен самостоятельно принимать решение, слова какого размера нужно загружать, а какого размера нет.  
Значение минимального размера слова класс должен принимать в конструктор так же, как путь к файлу. 

**6. Реакция на ошибки**

Если по указанному адресу в  не будет найден файл со словами, то программа аварийно вылетит через Exception и напечатает непонятные для юзера сообщения в консоль
```java
Exception in thread "main" java.lang.RuntimeException: Файл '/russian-nouns.txt_fck' не найден в classpath.
	at ru.hangman.WordProvider.getRandomWord(WordProvider.java:21)
```
Здесь должна быть другая реакция на отсутствие файла со словами.  
Нужно сказать юзеру, что файл со словами по указанному пути открыть не удалось и поэтому работа программы будет завершена. 

После этого нужно корректно, а не аварийно, завершить работу программы.

**7.class ConsoleView**

Класс распечатывает текстовые сообщения.

+ 👍 Слой View.

Благодаря тому, приём данных от юзера и распечатка текстов для юзера производятся через этот класс, в программе появляется слой Вью.
То есть, в программе логика отделена от представления. Это хорошо. 

+ 👍 SRP методов.

Методы работают правильно: они просто принимают данные от юзера или распечатывают тексты.  
Эти методы не содержат частей общей игровой логики, за которую должны отвечать "более интеллектуальные" классы. 

- Придерживайся единообразия в названиях.

Эти два метода выполняют одинаковые операции- получают от юзера какие-то данные.  
Их префиксы должны быть одинаковы точно так же, как у всех методов распечатки есть одинаковый префикс "print"
```java
public char readLetter() {...}

//ПРАВИЛЬНО:
```

**9. class GameState**

+ 👍 Этот класс похож на движок игры, движок это хорошо.

Движок это вся игровая логика без взаимодействия с представлением.  
Игровая логика с взаимодействием с представлением в таких случаях выносится в отдельный контроллер.  
Здесь движок это `GameState`, а контроллер- `Game`.

**10. class Game**

+ 👍 Контроллер движка `GameState`.

Контроллер движка должен содержать только ту игровую логику, которая зависит от представления.

- Нарушение SRP.

Контроллер должен получать в себя уже готовый движок, а не создавать его внутри себя

```java
    Scanner scanner = new Scanner(System.in);

//ПРАВИЛЬНО:
public class Game {
  private final GameState state;

    this.state = state;
```

## АРХИТЕКТУРА

Хотя в программе в названиях нет отсылок к архитектуре MVC, кроме слова "View" в названии одного из классов, эта реализация соответствует архитектуре MVC.  
По своему функционалу классы относятся к трём слоям: модель, вью, контроллер. И их ответственности между собой не смешиваются. 

**Но декомпозиция моделей на базовом уровне ООП здесь очень простая.**  

Не выявлены и не сделаны в виде классов более сложные, чем Словарь, сущности-модели.  
Например, сущность "Секретное слово".

Возможно, понимание декомпозиции на базовом ООП уровне у тебя не такое хорошее, как умение разделять классы по слоям в архитектуре MVC.  
К разделению классов по слоям MVC особых замечаний нет, всё ок.
