## ЗАМЕЧАНИЯ

**1. Нейминг**

- Этот сканер не может быть глобальным- его зона видимости ограничена методом, внутри которого он находится  
```java
void main(String[] args) {
  Scanner globalScanner = new Scanner(System.in);
  //...
  startGameLoop(globalScanner)
}

//ПРАВИЛЬНО:
void main(String[] args) {
  Scanner scanner = new Scanner(System.in);
  //...
  startGameLoop(scanner)
}
```
То, что сканер перекидывается между методами, не делает его глобальным.  
У термина "глобальная переменная" в программировании имеется своя определенная коннотация.

- Хуже венгерской нотации только венгерская нотация, которая обманывает. 

Здесь в названии переменной имеется слово "Char", но эта переменная не принадлежит к типу `char`, это `int`.
```java
int errorChar = 0;

//ПРАВИЛЬНО:
int errorCounter = 0;
```
Не пиши в названии переменных тип данных- это венгерская нотация и это плохо.

- Не сокращай слова без особой нужды
```java
String dict

//ПРАВИЛЬНО:
String dictionary
```

Сокращения приводят к тому, что ты потом сам путаешься, что хотел сказать названием:
```java
private static boolean applyGuess(String dict, char[] mask, char guess) {
  //открывает букву в маске слова dict
}

//ПРАВИЛЬНО:
private static boolean applyGuess(String word, char[] mask, char guess) {
  //открывает букву в маске слова word
}
```

- Название обманывает.

Этот метод не показывает меню. Он принимает команду от юзера
```java
private static int showMenu() {
  System.out.println("ГЛАВНОЕ МЕНЮ");
  System.out.println("1. Начать игру");
  System.out.println("2. Выход");
  //...
  return scanner.nextInt();
}

//ПРАВИЛЬНО:
private static int inputStartCommand() {...}
```

- Придерживайся единообразия
```java
private static boolean winGame(char[] mask, String word) {...}
private static boolean isLose(int errors) {...}

//ПРАВИЛЬНО:

```

**6. Exceptions**

- Текст в Exception всегда должен быть на английском языке.
```java
throw new IOException("Словарь пустой");  <-- Неправильно: сообщение в исключении не на английском языке
```
Исключение это не просто телеграмма, которая летит сквозь слои.

У exception особое назначение- если исключение вылетит и не будет перехвачено внутри программы, то аварийно прекратит выполнение программы.  
Тогда на экране будет распечатано сообщение эксепшена, и это сообщение должно быть понятно сисадмину в любой точке планеты.  
А значит, сообщение должно быть на английском.

Интерпретация исключения и перевод его на локальный язык должны происходить там, где это соответствует архитектуре программы.  
Или не происходить вовсе, если исключение не планируется перехватывать.

- Проверяемые исключения перехватывай в точке их возникновения и заменяй на непроверяемые. 

Проброс исключений в сигнатуре методов захламляет код.  
Поэтому заменяй проверяемые исключения на непроверяемые  
```java
private static String getRandomWordFromFile(String fileName) throws IOException {

  BufferedReader reader = new BufferedReader(new FileReader(fileName));
  while ((line = reader.readLine()) != null) {...}
  //...
}

//ПРАВИЛЬНО:
private static String getRandomWordFromFile(String fileName) {
  try {
    BufferedReader reader = new BufferedReader(new FileReader(fileName));
    while ((line = reader.readLine()) != null) {...}
  } catch(IOException e) {
    throw new КакоетоНепроверяемоеИсключение(e);
  }
  //...
}
```
Изучи различия проверяемых и непроверяемых исключений  
*"ЧК", гл.7, "...проверяемые исключения"*

**8. Рекурсия**

В алгоритме программы есть рекурсия
```java
+-->  private static Character readGuess(Scanner scanner) {  
|       //...                                                   
|       if (!input.matches("[а-я]")) {                           
+-------- return readGuess(scanner);  
        }
      }
```

Рекурсия должна использоваться только там, где она оптимальна алгоритмически.
Например, при обходе бинарного дерева.

В других ситуациях, где рекурсия может быть заменена циклом, она должна быть им заменена.  
Рекурсия тяжело читается и при определенных условиях может привести к переполнению стека.  
Убери рекурсию, замени ее использование на цикл `while()`. 

Условный пример
```java
//❌ ПЛОХО:
void start() {
  printMessage("Введите команду: 0-выйти, 1-играть");  
  int command = inputCommand();

  if(command == 0) {
    return;
  } 

  if(command == 1) {
    playGame();
  } 

  start();  <-- РЕКУРСИЯ
}

//✔️ ХОРОШО:
void start() {
  while(true) {
    printMessage("Введите команду: 0-выйти, 1-играть");  
    int command = inputCommand();

    if(command == 0) {
      return;
    } 

    if(command == 1) {
      playGame();
    } 
  }  
}
```

**11. Совмещение команд и запросов**

Этот метод делает два дела сразу и совмещает команду и запрос
```java
private static boolean applyGuess(String dict, char[] mask, char guess) {
  boolean found = false;

  for (int i = 0; i < dict.length(); i++) {
    if (Character.toLowerCase(dict.charAt(i)) == guess) {
      mask[i] = dict.charAt(i);    <-- ВЫПОЛНЕНИЕ КОМАНДЫ
      found = true;
    }
  }
  return found;  <-- ОТВЕТ НА ЗАПРОС  
}
```
Здесь два дела: проверка того, что буква есть в слове и открытие буквы.  
Команда: открыть букву в маске.  
Запрос: сказать, есть ли буква в слове.

Методы должны делать только каждый одно дело и не совмещать команды и запросы
```java
"Либо функция изменяет состояние объекта, либо возвращает информацию об этом объекте. 
Совмещение двух операций часто создает путаницу." - Мартин.
```

Здесь должно быть примерно так:
```java
boolean isWordLetter(String word, char letter) {...}

void updateMask(String word, char[] mask, char letter) {
  //открывает букву в маске
  //если такой буквы нет в слове- бросает исключение
}
```

**15. Печать картинок**

Неочевидный, неподдерживаемый и нерасширяемый способ рисовать виселицу
```java
private static void printGallows(int errors) {
  System.out.println(" +---+");
  System.out.println(" |  |");
  if (errors >= 1) {
    System.out.println(" O  |");
  } else {
    System.out.println(" |");
  }
  //...
}
```
Из-за того, что из кода непонятно, что в итоге напечатается, получилась не виселица, а кол:
```

 |  |
 O  |
/|\ |
/ \ |
 |
=========
```

Картинки нужно хранить в статическом массиве и печатать по номеру.

```java

   ,

  private static void printPicture(int number) {

```

**16. Большой божественный метод**

Слишком большой метод `startGameLoop(...)` размером 50 строк.  
Божественные методы разделяй на маленькие методы, каждый из которых должен делать одно дело на одном уровне абстракции.

Например, в этом методе два вложенных вечных цикла, каждый из которых решает какую-то свою задачу
```java
private static void startGameLoop(Scanner scanner) {
  while (true) {
    //Логика создания и запуска нового игрового раунда

    while (true) {
      //логика игрового раунда
    }
  }
}
```
Эти задачи нужно разделить на разные методы.
