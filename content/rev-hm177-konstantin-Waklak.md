## ЗАМЕЧАНИЯ

**1. Нейминг**

- Вычурные названия
```java
public class ConstructionPrint {
 
  public void printConstruct(int n) {...}
}

//ПРАВИЛЬНО:
public class HangmanPrinter {
 
  public void print(int picNumber) {...}
}
```
Кроме того, названия классов должны быть существительными, а методов- глаголами.  
"Print"- глагол, "Printer"- существительное.

- Не сокращай названия без необходимости, особенно если сокращения неочевидны.

Кто такой "res"? Restaurant, reservation or else?
```java
List<Character> res = new ArrayList<>();
```

- Н вбрсв глсн в нзвнх
```java
Random rnd = new Random();

//ПРАВИЛЬНО:
Random random = new Random();
```

- Переменные пишутся с маленькой буквы
```java
String Word = words.get(rnd.nextInt(words.size()));

//ПРАВИЛЬНО:
String word = words.get(rnd.nextInt(words.size()));
```

- Названия методов должны быть глаголом.

"Choiсe" - выбор, "choose" - выбирать.  
По правилам английского языка, сначала пишется глагол, потом дополнение.
```java
List<Character> wordChoise(String filename)

//ПРАВИЛЬНО:
List<Character> chooseWord(String filename)
```

*Oracle Java code conventions, part."Naming conventions"*  
*Мартин, "Чистый код", гл.2*

**2. Нарушение конвенции кода**

- Скобочки.

В любой ситуации выделяй тело блока скобочками, даже если тело состоит из одной строки  
```java
if (input.length() == 1) {
  //...  
} else return false;

//ПРАВИЛЬНО:
if (input.length() == 1) {
  //...  
} else {
  return false;
}
```
Исключение- метод equals(), там можно после if не выделять блоки скобочками.  
*"Oracle Java code conventions"*  

**3. Форматирование строк**

- Мысленные преобразования.

Не вставляй перевод строки в середину строк при распечатке.  
Иначе при чтении кода приходиться мысленно "разворачивать" одну строку в несколько.  
Если нужно распечатать несколько строк, то печатай их или многострочными строками(""") или отдельными инструкциями печати.  
Тогда сразу будет видно, как текст будет выглядеть на печати:
```java
System.out.println("|\n|\n|\n|\n|");

//ПРАВИЛЬНО:
System.out.println("|");
System.out.println("|");
System.out.println("|");
System.out.println("|");
System.out.println("|");
```

Аналогично:
```java
System.out.println("\n\nВЫ ЗАКОНЧИЛИ ИГРУ\nхотите начать новую[N] или выйти[E]");

//ПРАВИЛЬНО:
System.out.println();
System.out.println();
System.out.println("ВЫ ЗАКОНЧИЛИ ИГРУ");
System.out.println("хотите начать новую[N] или выйти[E]");
```

- Избыточно
```java
System.out.println("----------------");
System.out.print("|\n");
System.out.print("|\n");
System.out.print("|\n");

//ПРАВИЛЬНО:
System.out.println("----------------");
System.out.println("|");
System.out.println("|");
System.out.println("|");
```

- Ты всё равно написал в несколько строк, так напиши их красиво и понятно
```java
System.out.println("Игра виселица. Ты должен угадать слово по одной букве\n" +
   "В начале тебе даётся 7 попыток\n" +
   "После каждой неверной буквы будет рисоваться часть виселицы\n\n");

//ПРАВИЛЬНО:
System.out.println("Игра виселица. Ты должен угадать слово по одной букве");
System.out.println("В начале тебе даётся 7 попыток");
System.out.println("После каждой неверной буквы будет рисоваться часть виселицы");
System.out.println();
System.out.println();
```

**4. Если в блоке if есть return(break, continue, throw, exit и т.д.), то else не пишется**  
В этом случае неважно, будет else или нет, так как программа будет работать одинаково, а код без else будет выглядеть читабельней
```java
if (used.contains(input.charAt(0))) {
  System.out.println("Нельзя повторно вводить одинаковые символы");
  return false;
} else {
  used.add(input.charAt(0));
  return true;
}

//ПРАВИЛЬНО:
if (used.contains(input.charAt(0))) {
  System.out.println("Нельзя повторно вводить одинаковые символы");
  return false;
} 
used.add(input.charAt(0));
return true;
```

**7. class CheckInput**

- Нейминг.

Название класса не соответствует тому, что делает класс.  
Класс не проверяет ввод. Прежде всего, он осуществляет сам ввод.

- Нарушение инкапсуляции.
```java
public class CheckInput {
  public List<Character> used = new ArrayList<>();
  //...
}
```
Все поля должны быть приватными, а доступ к ним- только через геттеры и сеттеры.  
Для прямого использования потомками, некоторые поля могут быть `protected`.  
*Блох "Java. Эффективное программирование", изд.3, гл.4.2*

- Не нужно писать пустой конструктор, если кроме него нет других конструкторов
```java
public class CheckInput {
  public List<Character> used = new ArrayList<>();

  public CheckInput() {
  }

  public boolean checkKeyboardInput(String input) {...}
}

//ПРАВИЛЬНО, класс с конструктором по умолчанию:
public class CheckInput {  
  private List<Character> used = new ArrayList<>();

  public boolean checkKeyboardInput(String input) {...}
}
```
В этом случае будет работать конструктор по умолчанию, который идентичен пустому конструктору.

- Несколько разных ответственностей в классе.

Если рассматривать этот класс с точки зрения ООП, то его нужно разделить на несколько, у каждого из которых будет свой SRP. 

Один класс должен принимать от юзера ЛЮБОЙ одиночный символ.  
Второй класс должен валидировать этот символ- проверять, является ли этот символ русской буквой.  

Например:
```java
public class Dialog {

      //получить от юзера строку

      //Если строка состоит не из одного символа- напечатать fail
    }
  }    
}

public class RusLetterValidator {
  
  public boolean isValid(char symbol) {
    //возвращает true если symbol это русская буква 
  }    
}
```

А использованные буквы хранить и пополнять нужно где-то в другом месте. 

- Нарушение правила одной операции. 

Этот метод делает несколько разных вещей сразу
```java
public boolean checkKeyboardInput(String input) {
  //Получает букву от юзера
  //Заносит букву в список использованных
  //etc
}
```
Метод нужно разделить на несколько, каждый из которых будет делать что-то одно.

Публичным тут должен быть только метод `main`.

- Куча магических слов, букв, цифр. Вводи константы

- Большой божественный метод `main()` на 70 строк.

Детально обсуждать этот метод не имеет смысла- он ужасен.

Метод нужно разделить на несколько, которые будут соответствовать этим критериям:  
🔹 Маленький размер  
🔹 Выполняют одну операцию на одном уровне абстракции  
🔹 Не совмещают команду и запрос  
🔹 Не содержат больше трех уровней вложенности  

Подробнее про методы: 3 глава "ЧК" и ролик Немчинского "Правильные методы по Clean Code" на ютубе.
