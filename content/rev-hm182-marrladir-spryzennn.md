- Не дублируй имя класса в названии метода класса
```java

}

//ПРАВИЛЬНО:
public class Game {
  public void start() {...}
}
```

- Формулируй понятно, но лаконично
```java
public boolean isCharInWord(char c, String chosenWord) {...}

//ЛУЧШЕ:
public boolean isWordLetter(String word, char letter) {...}
```

- Формулируй яснее.

Этот метод буквально называется "обновить маску".  
Но при этом в методе нигде не используется переменная с названием "маска".  
И только внимательно изучив код, становится понятно, что под "маской" понимается "blanksWord".  
Если это маска, то и назови её маской

**4. class Word**

- Ответственность класса.

В ООП программе каждый класс должен собой представлять какую-то определенную сущность. 

Рассмотрим, что делает этот класс:  
🔹Читает слова из файла  
🔹Возвращает случайное слово и маску этого слова   
🔹Хранит использованные буквы   
🔹Проверяет наличие буквы в слове   
🔹Открывает букву в маске 

Этот класс собой не представляет никакой определенной сущности, это контейнер функций в стиле процедурного программирования. 

- Путь к файлу класс должен получать в конструктор. 

Иначе класс становится не универсальным.  
Допустим, в программе будет несколько разных текстовых файлов- на разных языках или по разным темам.  
Тогда вместо нескольких специализированных классов Словаря, где имя файла словаря будет жестко прописано в каждом из классов, 
можно будет использовать один универсальный класс Словарь.

- Не возвращай из метода результат в виде массива, если элементы массива имеют разный смысл.

Возврат массива, в котором каждый его элемент имеет разный смысл, это типичный приём процедурного программирования.  
В ООП в аналогичных ситуациях используй кастомные классы:
```java
public String[] getRandomTwoWords() {
  Random random = new Random();
  String chosenWord = words.get(random.nextInt(words.size()));
  String blanksWord = "_".repeat(chosenWord.length());

  return new String[]{chosenWord, blanksWord};
}

//ПРАВИЛЬНО:
public WordWithMask getRandomWordWithMask() {
  Random random = new Random();
  String word = words.get(random.nextInt(words.size()));
  String mask = "_".repeat(word.length());

  return new WordWithMask(word, mask);
}

public record WordWithMask(String word, String mask){
}
```
- Побочный эффект. 

Судя по названию, метод должен только проверить, использовалась ли эта буква.    
Однако метод ещё неявно изменяет состояние объекта: если буквы нет в `usedChars`, она добавляется в этот список
```java
public boolean isCharUsed(char c) {
  char lowerC = Character.toLowerCase(c);
  return !usedChars.add(lowerC);
}
```
Таким образом, вызов метода `isCharUsed(...)` не только проверяет состояние объекта, но и изменяет его.  
Это неожиданный побочный эффект, который не отражён в названии метода.

Метод нужно разделить на несколько, каждый из которых будет выполнять только одну задачу.  
Например:
```java
boolean isUsedLetter(char letter) {...}
void addUsedLetter(char letter) {...}
```

**7. class Game**

- Большой божественный метод.

Ацкий ад- метод `runGame()` размером 60 строк.  
Этот метод вообще нечитаем. 

Божественные методы разделяй на маленькие методы, каждый из которых должен делать одно дело на одном уровне абстракции.  

Например, смотрим на божественный метод и находим в нем отдельные смысловые блоки
```java
public void runGame() {
  //куча кода

  System.out.print("Покинуть игру(да/нет): ");
  String choice_exit_game = sc.nextLine().toLowerCase();

  while ((!choice_exit_game.equals("нет")) && (!choice_exit_game.equals("да"))) {
    System.out.println("Неправильный ввод. Попробуйте ещё раз");
    System.out.print("Покинуть игру(да/нет): ");
    choice_exit_game = sc.nextLine().toLowerCase();
  }

  //ещё куча кода
}
```

Что делает этот кусок кода? Он принимает от юзера команду начать игру или выйти из игры.  
Выносим этот код во вспомогательный метод:
```java
private static final String START = "да";
private static final String QUIT = "нет";

public void start() {
  //куча кода

  String command = inputCommand(); //Вернет только START или QUIT

  //ещё куча кода
}

private String inputCommand() {
  System.out.printf("Начать игру(%s/%s): ", START, QUIT);

  while(true) {
    String command = scanner.nextLine().toLowerCase();
    if (command.equals(START) || command.equals(QUIT)) {
      return command;
    }
    System.out.println("Неправильный ввод. Попробуйте ещё раз");
  }    
}
```
*"ЧК", гл.3, "Правило одной операции", "Один уровень абстракции"*
 
- Метод не должен завершать работу программы через exit()
```java
public void runGame() {
  //...
  exit(0);
  //...
}
```
Каждый метод и класс имеют право завершать только свою работу. Например, через return.  
Потому что методы и классы не должны знать логику работы более высоких слоев программы, у которых могут быть свои планы на тему того, когда и почему нужно завершать работу программы.

Кроме того, при выходе через `exit()` могут не закрыться некоторые ресурсы программы.

## АРХИТЕКТУРА

Несмотря на то, что в проекте несколько классов, он написан в процедурном стиле.  
Программа в ООП стиле должна быть декомпозирована по правилам ООП и использовать ООП-подход для реализации типичных задач.  
Здесь не видно ООП декомпозиции.

И в процедурном и в ООП стиле методы должны соответствовать таким требованиям:  
🔹 Маленький размер  
🔹 Выполняют одну операцию на одном уровне абстракции  
🔹 Не совмещают команду и запрос  
🔹 Не содержат больше трех уровней вложенности  
🔹 Не имеют побочных эффектов

Сейчас большинство методов в программе нарушают те или иные из этих требований.
