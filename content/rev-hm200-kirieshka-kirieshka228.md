## ЗАМЕЧАНИЯ

**1. Нейминг**

- Названия методов должны быть глаголом в повелительном наклонении. Это название - существительное
```java
void mainMenu()
```

- Две переменные с названиями, похожими до уровня смешивания
```java
String word = "";
char[] inputWord;

//ПРАВИЛЬНО:
String word = "";
char[] mask;
```

- Константы это поля классов, а не переменные методов. 

Писать стилем UPPER_SNAKE можно только константы. 
Обычные не статические поля, даже если они final, нужно писать стилем camelCase
```java
public class Game {
  private static final String PATH = "Words.txt";
  //...

  private void playGame() {
    final String CONGRATULATIONS = "Поздравляю! Вы победили!!!";
    final String LOOS = "Вы потратили все попытки.";
    //...
  }
}

//ПРАВИЛЬНО ИЛИ ТАК:
public class Game {
  private static final String PATH = "Words.txt";
    static final String CONGRATULATIONS = "Поздравляю! Вы победили!!!";
    static final String LOOS = "Вы потратили все попытки.";
  //...

  private void playGame() {
    //...
  }
}

//ИЛИ ТАК:
public class Game {
  private static final String PATH = "Words.txt";
  //...

  private void playGame() {
    final String congratulations = "Поздравляю! Вы победили!!!";
    final String loos = "Вы потратили все попытки.";
    //...
  }
}
```

- Не дублируй имя класса в названии метода класса
```java
Game.playGame();

//ПРАВИЛЬНО:
Game.play();
```

**2. Нарушения конвенции кода**

- Скобочки.

В любой ситуации выделяй тело блока скобочками, даже если тело состоит из одной строки  
```java
if (errors >= 0) IO.println(" |   |");
if (inputWord[i] == word.charAt(i)) win = true;

//ПРАВИЛЬНО:
if (errors >= 0) {
  IO.println(" |   |");
}

if (inputWord[i] == word.charAt(i)) {
  win = true;
}
```
Исключение - метод equals(), там де-факто разрешается после `if` не выделять блоки скобочками. 

*"Oracle Java Code Conventions"* 

**3. Форматирование**

- Форматирование строк.

Если нужно печатать или создавать строку с более чем одним подстановочным значением или значение вставляется внутрь сообщения, 
используй форматирование - тогда сразу будет виден весь шаблон сообщения
```java
IO.println(CONGRATULATIONS + " Слово: \"" + word + "\", у вас " + claims + " очков!");

//ПРАВИЛЬНО:
IO.printf(CONGRATULATIONS + " Слово: '%s', у вас %d очков! \n", word, claims);
```

- Мысленные преобразования.

Не вставляй перевод строки в середину строк при распечатке.  
Иначе при чтении кода приходится мысленно "разворачивать" одну строку в несколько.  
Если нужно распечатать несколько строк, то печатай их или многострочными строками(""") или отдельными инструкциями печати.  
Тогда сразу будет видно, как текст будет выглядеть на печати:
```java

    """;
```

Поэтому заменяй проверяемые исключения на непроверяемые

**7. Определение русской буквы**

- Этот метод определяет не кириллическую букву.

Метод определяет русскую букву, а это не одно и то же
```java
private boolean isCyrillic(char symbol) {
  int code = (int) symbol;
  return (code > 1040 && code < 1103) || code == 1025 || code == 1105;
}
```

- Неправильная работа с char.

Каждый символ имеет свой цифровой код в таблице Unicode, поэтому можно напрямую буквы сравнивать как цифры 
```java
return (code > 1040 && code < 1103) || code == 1025 || code == 1105;

//ПРАВИЛЬНО (С ТОЧКИ ЗРЕНИЯ ИСПОЛЬЗОВАНИЯ CHAR):
return (code > 'А' && code < 'я') || code == 'ё' || code == 'Ё';
```
Почитай про то, как символы хранятся в таблице Unicode.

- Если сравнивать символы через `char`, а не через `int`, то сразу видно, где у тебя будет ошибка:
```java
return (code > 'А' && code < 'я') || code == 'ё' || code == 'Ё';
```

```java
private void drawHangman(int errors) {
  IO.print("\033[H\033[2J");
  System.out.flush();
  IO.println(" +---+");
  if (errors >= 0) IO.println(" |   |");
  if (errors >= 1) IO.println(" 0   |");
```

При написании программы, главный приоритет - простота и понятность кода.

Картинки нужно хранить в статическом массиве и печатать по номеру.

**12. Божественный метод** 

В этом методе 60 строк: `playGame()`  
Из-за своей запутанности и большого размера, этот метод почти нечитаем.

Если какой-то метод получается ощутимо длинным, то есть больше 20-30 строк, то скорее всего, он делает много разных дел одновременно.  
Такой метод нужно сокращать: выявить в нём отдельные смысловые блоки и вынести их во вспомогательные методы.

Например, смотрим на божественный метод и находим в нём отдельные смысловые блоки
```java
private void playGame() {
  //куча кода
  for (int i = 0; i < word.length(); i++) {
    if (inputWord[i] == word.charAt(i)) win = true;
      else {
        win = false;
        break;
      }
    }
  }

  // ещё куча кода
}
```

Что делает этот кусок кода? Он проверяет на выигрыш.  
Выносим этот код во вспомогательный метод:
```java
private static String word;
private static char[] mask;
//...

private void playGame() {
  //куча кода
  if (isWin()) {
    // действия при выигрыше
  }

  // ещё куча кода
}

private static boolean isWin() {
  for (int i = 0; i < word.length(); i++) {
    if (mask[i] != word.charAt(i)) {
      return false;    
    }
  }
  return true;
}
```

Писать божественные методы - это плохо даже для процедурного стиля. 

*"ЧК", гл.3, "Компактность", "Правило одной операции", "Один уровень абстракции"*

**13. Создавай вспомогательные методы, делай программу более простой и понятной**
```java
private void playGame() {
  while (!win && errors < 6) {...}
}

//ПРАВИЛЬНО:
private static final int MAX_ERROR = 6;

private static int error;

private void playGame() {
  while (!isGameOver()) {...}
}

private boolean isGameOver() {
  return isWin() || isLose();
}

private static boolean isLose() {
  return error >= MAX_ERROR;
}
```
Даже если метод состоит из одной строки, но при этом делает код программы читабельнее, то этот метод имеет право на жизнь.
